## 문제 1. 운영 화면이 서비스 수만큼 흩어져 있었다

### 상황

마켓봄 에코시스템이 마켓봄프로·도매·마켓봄으로 확장되면서, **각 서비스의 운영 업무를 처리하는 내부 도구가 서비스마다 따로 존재**했습니다.

운영팀은 서비스마다 별도 화면을 오가야 했고, **서비스 간 데이터를 비교하는 일이 특히 어려웠습니다.** 같은 기간의 정산을 보려 해도 도구를 옮겨 다니며 각각 조회해야 했습니다.

### 제약

기존 어드민은 Vue/Nuxt 기반이었습니다. 세 서비스의 화면을 그 위에 합치는 방법도 있었지만, 통합 대상 화면 대부분이 **어차피 새로 만들어야 하는 것**이었습니다. 레거시 위에 얹으면 낡은 구조를 그대로 물려받은 채 시작하게 됩니다.

### 접근과 결정

**레거시와 분리해 React 18 + Vite로 새로 세우는 쪽을 택했습니다(0→1).** 기존 어드민은 그대로 두고, 통합 대상 화면만 신규 프로젝트로 옮기는 방식입니다.

세 서비스를 하나의 화면에서 다루려면 **"지금 어느 서비스를 보고 있는가"가 화면 곳곳에 영향**을 줍니다. 선택된 사업부·날짜 범위 같은 상태를 `Recoil` 원자 단위로 두어, 이 값이 바뀔 때 다시 그려야 하는 영역만 반응하도록 했습니다.

대용량 정산 데이터는 `ag-Grid` 커뮤니티 에디션으로 **클라이언트에서 정렬·필터링·그룹핑**하도록 했습니다. 재무팀의 조회는 조건을 계속 바꿔가며 들여다보는 성격이라, 조건마다 서버를 왕복하면 작업 흐름이 끊깁니다.

### 결과

**세 서비스로 흩어져 있던 운영 화면을 단일 어드민으로 통합**해, 운영팀이 서비스마다 별도 도구를 오가던 동선을 제거하고 서비스 간 데이터 비교가 가능해졌습니다.

정산 초기화의 진행 중·반려 상태를 화면에서 관리하도록 모델링해, 재무팀이 처리 단계를 추적할 수 있게 했습니다. 공지 게시·롤링 설정은 운영팀에 이관해 **공지 변경마다 개발자를 거치던 과정을 없앴습니다.**

### 한계

**운영팀의 업무 시간 변화를 측정하지 않았습니다.** 동선이 줄었다는 것은 구조상의 사실이지만, 그것이 실제로 얼마나 시간을 아꼈는지는 확인하지 않았습니다.

또한 통합은 **신규 구축 범위에 한정**됩니다. 레거시 어드민에 남은 화면은 그대로 남아 있어, 운영팀이 두 도구를 쓰는 상태가 완전히 사라진 것은 아닙니다.

## 문제 2. 스키마가 바뀌면 프론트가 조용히 틀린다

### 상황

어드민은 GraphQL API 위에서 동작하는데, **스키마 변경이 프론트엔드에 자동으로 전달되지 않았습니다.** 필드명이 바뀌거나 타입이 달라져도 빌드는 통과하고, 문제는 화면을 열었을 때 드러납니다.

정산 데이터를 다루는 화면에서 이런 오류는 "화면이 안 뜬다"보다 **"값이 잘못 보인다"** 쪽으로 나타나기 쉽습니다. 재무 업무에서는 후자가 더 위험합니다.

### 접근과 결정

**GraphQL Code Generator를 도입해 스키마에서 TypeScript 타입과 Apollo 훅을 자동 생성**하도록 했습니다. 손으로 타입을 맞춰 쓰는 대신 스키마를 단일 출처로 두는 것입니다.

이렇게 하면 API 스키마가 바뀌었을 때 **프론트엔드 타입이 함께 바뀌고, 어긋난 곳이 빌드 타임에 컴파일 오류로 드러납니다.** 런타임에 잘못된 값이 표시되는 대신, 배포 전에 멈추게 됩니다.

### 결과

**API-프론트 타입 동기화가 자동화되어, 스키마 변경으로 인한 타입 불일치가 빌드 단계에서 검출됩니다.**

## 그 밖의 담당 기여

### 정산·매입처 관리 화면

- **정산 집계** — 기간·유통사·거래처 조건으로 거래 내역을 필터링하고 합산하는 집계 인터페이스
- **매입처 관리** — 매입처 등록·수정·조회 화면. 임시 아이디 대소문자 표시 오류 수정, 매입처 필드 GraphQL 연동
- **초기화 처리** — 정산 초기화 진행 중·반려 상태 관리 화면. 상태 전환 흐름을 React 상태로 모델링

### 공지 관리 기능

운영팀이 서비스별로 공지를 게시·수정하는 화면을 구현했습니다. 공지 대상(매출처·매입처) 필터링, 리치 텍스트 편집기(React-Quill) 연동, 공지 롤링 설정(종료일·제한 없음 옵션) 등을 담당했습니다.
