## 배경

> *"당신이 쌓은 돌 하나가 누군가의 하루를 버티게 합니다."*

길가의 돌탑 문화에서 영감을 받았습니다. 지나는 이마다 돌을 하나씩 얹으며 안녕을 빌었던 전통처럼, 사용자들이 익명의 공간에서 고민이나 소원을 내려놓고, 타인의 이야기 위에 위로를 얹을 수 있는 서비스를 만들었습니다.

SNS에는 자신을 드러내기 어렵고, 가까운 지인에게는 솔직하기 어려운 순간이 있습니다. 이 간극을 해소하기 위해, 선함연구소라는 개인 브랜드 아래 완전한 익명성을 보장하면서도 진심 어린 위로가 오가는 커뮤니티를 기획·설계·개발·운영하고 있습니다.

2026년 3월 iOS App Store, Google Play에 정식 출시했습니다.

## 1.x → 2.x: 순수 네이티브 전면 재구현

출시 당시의 1.x는 React 웹 앱을 WebView로 감싼 하이브리드였습니다. 배포가 빠르다는 장점은 분명했지만, 대가가 누적됐습니다.

- 사용성·애니메이션의 천장이 낮았습니다. 시트·제스처·키보드 대응이 전부 웹 우회 구현이었습니다
- 브릿지가 계약이 되어버렸습니다 — Web→App 13종 / App→Web 7종, 브릿지 코드만 913 LOC
- 소셜 로그인처럼 네이티브 SDK가 필요한 기능마다 브릿지 왕복이 끼었습니다

2026년 7월, **WebView 폴백을 두지 않고 `apps/native`를 순수 네이티브로 다시 짓기로 결정**했습니다. 화면 1:1 이식이 아니라 **사용자 플로우 단위 재설계**로 접근하고, 시안은 문서가 아니라 동작하는 화면 두 벌을 만들어 실기기에서 비교해 확정했습니다. UI는 전부 새로 그렸지만 **GraphQL 프래그먼트·쿼리는 그대로 이식**해 데이터 레이어의 재작업을 피했습니다.

전환 기간 동안은 릴리즈를 중단하는 비용을 감수했습니다. 그 대신 이미 설치된 구버전 앱이 깨지지 않도록, 역할을 잃은 웹 앱 자리에 **업데이트 안내 정적 페이지 한 장**을 남겼습니다. 도메인을 내리면 구버전 사용자는 안내 대신 DNS 오류를 만나고, 서비스가 종료된 것이 아니라 고장 난 것처럼 보이기 때문입니다.

| | 1.x | 2.x |
|:---|:---|:---|
| 앱 본체 | React 웹 앱 (WebView) | React Native (순수 네이티브) |
| 라우팅 | TanStack Router | Expo Router |
| 애니메이션 | framer-motion | Reanimated 4 |
| 바텀시트 | vaul | `@gorhom/bottom-sheet` |
| 네이티브 기능 | `window.nativeBridge` 브릿지 | 네이티브 SDK 직접 호출 |
| 유지한 것 | — | Relay · Zustand · GraphQL 스키마 |

## 서비스 구조

```
돌들의 숲 (Turborepo 모노레포)
├── 네이티브 앱 (native)  — 앱 본체. React Native + Expo, WebView 없음
├── 백엔드 (backend)      — GraphQL API 서버 (Cloudflare Workers)
├── 어드민 (admin)        — 내부 운영 관리 콘솔
├── 랜딩 (landing)        — 서비스 소개 · 약관 · 다운로드 안내
└── (frontend)            — 구버전 앱 "업데이트 벽" 정적 페이지 한 장
```

## 핵심 은유 체계

| 서비스 용어 | 은유 | 의미 |
|:---|:---|:---|
| **원석** | 마음에 담은 돌 | 사용자가 숲에 내려놓는 고민이나 소원 |
| **조약돌** | 함께 쌓아가는 작은 돌 | 원석에 올려놓는 위로·응원 답변 |
| **쪽지** | 돌 사이에 끼워 넣은 종이 | 조약돌에 붙어 오가는 익명 대화 |
| **돌탑 완결** | 충분한 돌이 쌓인 탑 | 지정 개수 이상의 조약돌이 쌓인 상태 |

## 주요 기능

### 원석 · 조약돌 시스템
서비스의 핵심입니다. 사용자는 고민이나 소원을 **원석**(10~500자, 태그 1개)으로 올리고, 다른 사용자가 위로·응원을 **조약돌**(10~300자)로 쌓아줍니다. 완결 조건은 작성 시 5 / 10 / 15개 중에서 고르고, 조약돌이 그 수에 도달하면 돌탑이 완결되어 더 받지 않습니다.

원석은 수정·삭제 없이 숨김 처리만 가능합니다. 진정성 있는 기록으로 남기기 위한 의도적인 설계입니다. **완결 여부와 무관하게 생성 후 30일이 지나면 삭제**됩니다. 남기기 위해 쓰는 곳이 아니라 내려놓기 위해 쓰는 곳이라는 전제를 데이터 생명주기로 못 박았습니다.

### 쪽지 대화
조약돌에 한 번 붙이고 끝나던 단방향 감사 메시지를, **한 통씩 주고받는 대화**로 전환했습니다(ADR-007).

사람이 아니라 **조약돌에 붙는 대화**입니다. 서버는 닉네임을 내려주지 않고, 원석 작성자만 대화를 시작할 수 있으며 **교대 전송**으로만 이어집니다. 10일간 답이 없으면 스스로 끝나고, 끝난 대화는 7일 뒤 완전히 삭제됩니다. 익명성 원칙을 깨지 않으면서 대화를 허용하기 위한 제약들입니다.

### 다국어 — 원문 그대로, 번역은 기기가 한다
2.1.0에서 영어·일본어를 더했습니다. UI는 기기 언어를 따르고(인앱 전환 없음), 서버가 보내는 안내·알림·푸시 문장도 사용자 언어로 고릅니다.

다만 **사용자가 쓴 글은 번역하지 않습니다**. 다른 언어의 글은 원문 그대로 보이고, 읽고 싶을 때 기기 번역 기능(iOS Translation 시트 · Android `ACTION_PROCESS_TEXT`)으로 넘깁니다. 위로의 글에서 기계 번역의 오역은 비용이 너무 크고, 서버 번역은 원문이 무엇이었는지를 지워버리기 때문입니다.

### 가려진 조약돌 — 덮인 돌
차단·신고로 가려진 조약돌은 **돌탑에서 빠지지 않고 자리를 지킨 채 표면만 덮입니다**. 빼면 헤더의 정원 표시(`3 / 5`)와 화면에 쌓인 돌의 수가 어긋나고, "2/5인데 가득 찼어요"가 되기 때문입니다.

덮개는 둘로 나뉩니다 — 내가 차단해서 나에게만 가려진 것(되돌릴 수 있음)과, 공동체가 가린 것(되돌릴 수 없음). 화면에서는 같은 천으로 덮고 그 위의 낱말로만 가릅니다. **본문은 서버에서 비워 보냅니다** — 화면에만 맡기면 원문이 이미 기기에 도착해 있기 때문입니다. 돌 전체가 아니라 글이 새겨진 자리만 덮어, *돌은 그대로 있고 글만 가렸다*가 읽히게 했습니다.

### 안전 및 모더레이션
Apple App Store Guideline 1.2(UGC Safety)를 충족합니다.

| 기능 | 설명 |
|:---|:---|
| 발길질 (콘텐츠 차단) | 원석 10회, 조약돌 5회 누적 시 자동 숨김 |
| 사용자 차단 | 특정 사용자의 모든 콘텐츠를 피드에서 제거 |
| 신고 | 관리자 검토 후 7일 이내 처리 + 당사자 알림 |
| 이의 신청 | 인앱 이의 신청 → 승인 시 콘텐츠 복원 |
| 내 신고·위반 내역 | 접수 현황과 받은 조치를 사용자가 직접 확인 |

### 완전 익명 운영
닉네임·프로필 사진 없이 익명 캐릭터(쉐도우)로만 활동합니다. 소셜 로그인(Apple·Google)을 우선 경로로 두고, 기존 이메일 계정은 계속 로그인됩니다. 만 19세 이상만 가입 가능하며, **동시 로그인은 3대로 제한**됩니다 — 4대째 로그인하면 가장 오래된 기기가 끊깁니다.

### 오프라인은 가장 앞선 관문
연결이 끊기면 화면마다 다른 실패를 보여주는 대신 **한 화면으로 알립니다**. 그리고 기다리는 동안 할 일을 줬습니다 — 돌쌓기 미니게임이고, 최고 기록은 기기에만 남습니다.

## 담당 역할 & 기여

- **전체 기획 및 아키텍처 설계** — 서비스 개념 수립부터 모노레포 구조·기술 스택 선정까지
- **React Native 앱 개발** — Expo Router 기반 순수 네이티브 앱, Relay 데이터 레이어, Reanimated 4 애니메이션·제스처
- **WebView 하이브리드 → 순수 네이티브 전환** — 플로우 단위 재설계, 브릿지 913 LOC 제거, 구버전 사용자를 위한 업데이트 벽 설계
- **다국어 설계 및 구현** — 기기 언어 추종 i18n, 서버 발신 문구의 locale 분기, 기기 번역 위임 Expo 모듈 자체 작성
- **Cloudflare Workers 백엔드 개발** — GraphQL API 서버 구현 (Hono + GraphQL Yoga + Pothos)
- **데이터베이스 설계** — Prisma 스키마 설계 및 D1 마이그레이션 관리
- **실시간·레이트리밋 설계** — Durable Objects로 사용자당 소켓 하나로 모은 구독, 분산 Rate Limiting
- **랜딩 페이지 개발** — Astro 기반 서비스 소개 · 약관 · 개인정보 처리방침 (ko·en·ja)
- **내부 어드민 개발** — 콘텐츠 관리·사용자 지원·신고 처리를 위한 운영 콘솔
- **앱스토어 배포 및 운영** — iOS App Store, Google Play 출시 및 EAS 빌드 파이프라인 구성

### 기술 선택 이유

- **순수 네이티브 (WebView 폐기)**: 시트·제스처·키보드처럼 손에 가장 많이 닿는 부분이 웹 우회 구현의 천장에 걸려 있었습니다. 브릿지가 20종의 메시지 계약으로 굳어 네이티브 기능을 더할 때마다 왕복 비용이 들었습니다. 배포 속도를 잃는 대신 사용성의 상한을 올렸습니다.
- **Cloudflare Workers**: 서버 관리 부담 없이 글로벌 엣지 배포가 가능합니다. 콜드 스타트 없는 서버리스 환경으로 소규모 운영 비용을 최소화했습니다.
- **Durable Objects**: 서버리스 환경에서 WebSocket 실시간 구독(알림)과 분산 Rate Limiting을 상태 있는 DO 인스턴스로 처리했습니다. 구독은 화면마다 열지 않고 사용자당 소켓 하나로 모았습니다.
- **GraphQL + Relay**: 데이터 의존성을 컴포넌트 레벨에서 선언해 오버페칭을 방지하고 타입 안전성을 극대화합니다. 클라이언트·서버 스키마를 단일 패키지(`graphql-schema`)로 공유합니다. 네이티브 전환에서 UI를 전부 버리고도 데이터 레이어를 그대로 이식할 수 있었던 이유입니다.
- **theme 토큰 + StyleSheet (NativeWind 미채택)**: 디자인 토큰을 한곳에 두고 플랫폼 네이티브 스타일링을 그대로 씁니다. 웹 관습을 네이티브에 옮기는 레이어를 하나 줄였습니다.
- **Prisma + D1**: 서버리스 환경에 최적화된 SQLite 기반 DB로, 마이그레이션 관리와 타입 안전한 쿼리를 지원합니다.

## 성과 & 수치

- 2026년 3월 iOS App Store, Google Play 정식 출시 — 이후 2.x 메이저 전환까지 1인 운영
- WebView 하이브리드 → 순수 네이티브 전면 재구현 (브릿지 913 LOC 제거)
- 영어·일본어 추가로 UI·서버 문구·법률 문서까지 3개 언어 대응
- Android 릴리스 빌드에 R8 축소·난독화 적용 — dex 50.1MB → 16.6MB (−67%), 매핑 파일 포함으로 크래시 스택 자동 복원
- Cloudflare 서버리스 아키텍처로 서버 운영 비용 최소화
- 1인 개발·운영으로 기획부터 배포까지 전 사이클 담당
