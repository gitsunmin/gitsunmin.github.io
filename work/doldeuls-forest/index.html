소개

디지털 환경에서의 정서적 고립을 해소하고 싶어 만든 익명 P2P 힐링 커뮤니티입니다. 누군가와 연결되고 싶지만 신분을 드러내기 어려운 순간을 위해, 완전한 익명성을 보장하면서도 진심 어린 대화가 가능한 공간을 만들었습니다. 2026년 3월 1.x(WebView 하이브리드)로 정식 출시한 뒤, 2.0.0에서 순수 React Native 앱으로 전면 재구현하고 2.1.0에서 영어·일본어를 더했습니다.

배경

“당신이 쌓은 돌 하나가 누군가의 하루를 버티게 합니다.”

길가의 돌탑 문화에서 영감을 받았습니다. 지나는 이마다 돌을 하나씩 얹으며 안녕을 빌었던 전통처럼, 사용자들이 익명의 공간에서 고민이나 소원을 내려놓고, 타인의 이야기 위에 위로를 얹을 수 있는 서비스를 만들었습니다.

SNS에는 자신을 드러내기 어렵고, 가까운 지인에게는 솔직하기 어려운 순간이 있습니다. 이 간극을 해소하기 위해, 선함연구소라는 개인 브랜드 아래 완전한 익명성을 보장하면서도 진심 어린 위로가 오가는 커뮤니티를 기획·설계·개발·운영하고 있습니다.

2026년 3월 iOS App Store, Google Play에 정식 출시했습니다.

1.x → 2.x: 순수 네이티브 전면 재구현

출시 당시의 1.x는 React 웹 앱을 WebView로 감싼 하이브리드였습니다. 배포가 빠르다는 장점은 분명했지만, 대가가 누적됐습니다.

  • 사용성·애니메이션의 천장이 낮았습니다. 시트·제스처·키보드 대응이 전부 웹 우회 구현이었습니다
  • 브릿지가 계약이 되어버렸습니다 — Web→App 13종 / App→Web 7종, 브릿지 코드만 913 LOC
  • 소셜 로그인처럼 네이티브 SDK가 필요한 기능마다 브릿지 왕복이 끼었습니다

2026년 7월, WebView 폴백을 두지 않고 apps/native를 순수 네이티브로 다시 짓기로 결정했습니다. 화면 1:1 이식이 아니라 사용자 플로우 단위 재설계로 접근하고, 시안은 문서가 아니라 동작하는 화면 두 벌을 만들어 실기기에서 비교해 확정했습니다. UI는 전부 새로 그렸지만 GraphQL 프래그먼트·쿼리는 그대로 이식해 데이터 레이어의 재작업을 피했습니다.

전환 기간 동안은 릴리즈를 중단하는 비용을 감수했습니다. 그 대신 이미 설치된 구버전 앱이 깨지지 않도록, 역할을 잃은 웹 앱 자리에 업데이트 안내 정적 페이지 한 장을 남겼습니다. 도메인을 내리면 구버전 사용자는 안내 대신 DNS 오류를 만나고, 서비스가 종료된 것이 아니라 고장 난 것처럼 보이기 때문입니다.

주요 기능

원석 · 조약돌 시스템

서비스의 핵심입니다. 사용자는 고민이나 소원을 원석(10500자, 태그 1개)으로 올리고, 다른 사용자가 위로·응원을 조약돌(10300자)로 쌓아줍니다. 완결 조건은 작성 시 5 / 10 / 15개 중에서 고르고, 조약돌이 그 수에 도달하면 돌탑이 완결되어 더 받지 않습니다.

원석은 수정·삭제 없이 숨김 처리만 가능합니다. 진정성 있는 기록으로 남기기 위한 의도적인 설계입니다. 완결 여부와 무관하게 생성 후 30일이 지나면 삭제됩니다. 남기기 위해 쓰는 곳이 아니라 내려놓기 위해 쓰는 곳이라는 전제를 데이터 생명주기로 못 박았습니다.

쪽지 대화

조약돌에 한 번 붙이고 끝나던 단방향 감사 메시지를, 한 통씩 주고받는 대화로 전환했습니다(ADR-007).

사람이 아니라 조약돌에 붙는 대화입니다. 서버는 닉네임을 내려주지 않고, 원석 작성자만 대화를 시작할 수 있으며 교대 전송으로만 이어집니다. 10일간 답이 없으면 스스로 끝나고, 끝난 대화는 7일 뒤 완전히 삭제됩니다. 익명성 원칙을 깨지 않으면서 대화를 허용하기 위한 제약들입니다.

다국어 — 원문 그대로, 번역은 기기가 한다

2.1.0에서 영어·일본어를 더했습니다. UI는 기기 언어를 따르고(인앱 전환 없음), 서버가 보내는 안내·알림·푸시 문장도 사용자 언어로 고릅니다.

다만 사용자가 쓴 글은 번역하지 않습니다. 다른 언어의 글은 원문 그대로 보이고, 읽고 싶을 때 기기 번역 기능(iOS Translation 시트 · Android ACTION_PROCESS_TEXT)으로 넘깁니다. 위로의 글에서 기계 번역의 오역은 비용이 너무 크고, 서버 번역은 원문이 무엇이었는지를 지워버리기 때문입니다.

가려진 조약돌 — 덮인 돌

차단·신고로 가려진 조약돌은 돌탑에서 빠지지 않고 자리를 지킨 채 표면만 덮입니다. 빼면 헤더의 정원 표시(3 / 5)와 화면에 쌓인 돌의 수가 어긋나고, “2/5인데 가득 찼어요”가 되기 때문입니다.

덮개는 둘로 나뉩니다 — 내가 차단해서 나에게만 가려진 것(되돌릴 수 있음)과, 공동체가 가린 것(되돌릴 수 없음). 화면에서는 같은 천으로 덮고 그 위의 낱말로만 가릅니다. 본문은 서버에서 비워 보냅니다 — 화면에만 맡기면 원문이 이미 기기에 도착해 있기 때문입니다. 돌 전체가 아니라 글이 새겨진 자리만 덮어, 돌은 그대로 있고 글만 가렸다가 읽히게 했습니다.

기술 선택 이유

  • 순수 네이티브 (WebView 폐기): 시트·제스처·키보드처럼 손에 가장 많이 닿는 부분이 웹 우회 구현의 천장에 걸려 있었습니다. 브릿지가 20종의 메시지 계약으로 굳어 네이티브 기능을 더할 때마다 왕복 비용이 들었습니다. 배포 속도를 잃는 대신 사용성의 상한을 올렸습니다.
  • Cloudflare Workers: 서버 관리 부담 없이 글로벌 엣지 배포가 가능합니다. 콜드 스타트 없는 서버리스 환경으로 소규모 운영 비용을 최소화했습니다.
  • Durable Objects: 서버리스 환경에서 WebSocket 실시간 구독(알림)과 분산 Rate Limiting을 상태 있는 DO 인스턴스로 처리했습니다. 구독은 화면마다 열지 않고 사용자당 소켓 하나로 모았습니다.
  • GraphQL + Relay: 데이터 의존성을 컴포넌트 레벨에서 선언해 오버페칭을 방지하고 타입 안전성을 극대화합니다. 클라이언트·서버 스키마를 단일 패키지(graphql-schema)로 공유합니다. 네이티브 전환에서 UI를 전부 버리고도 데이터 레이어를 그대로 이식할 수 있었던 이유입니다.
  • theme 토큰 + StyleSheet (NativeWind 미채택): 디자인 토큰을 한곳에 두고 플랫폼 네이티브 스타일링을 그대로 씁니다. 웹 관습을 네이티브에 옮기는 레이어를 하나 줄였습니다.
  • Prisma + D1: 서버리스 환경에 최적화된 SQLite 기반 DB로, 마이그레이션 관리와 타입 안전한 쿼리를 지원합니다.
